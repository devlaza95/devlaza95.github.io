Jarvis privacy policy

Last updated 30 October 2026. Back to the Jarvis home page.

Who this covers

Jarvis is a personal assistant used by one person, its author, with the author's own Google account. It is not offered to anyone else. Mail in the author's inbox is written by other people; Jarvis handles it only as described below.

What Jarvis accesses

Access to the author's Gmail (gmail.readonly and gmail.compose) and read-only access to Google Calendar (calendar.readonly), granted by the author on Google's consent screen.

Jarvis uses the Gmail access to read mail, to write drafts in the author's own mailbox, and to send a draft, but only after the author has approved that exact message in Telegram, each time. Google's gmail.compose scope allows sending mail as the author; Jarvis uses that for nothing but a draft the author has approved. Jarvis does not label, archive, trash or delete mail, and it cannot change calendar events.

How it is used

To write a short summary, a category and a priority for each new message, to alert the author when a message needs attention, to answer the author's own questions about their mail and calendar, and to write draft replies and new drafts when the author asks for them. The author reads a draft, with its recipients and subject, before anything is sent. It is not used for advertising, profiling or any other purpose.

Where the data goes

  • Anthropic's API. The text of a new message (up to roughly 6,000 tokens, with attachment names but not attachment contents) and the calendar events the author asks about are sent to Anthropic's API, which runs the Claude model that writes the summary, the answer or the draft. A draft is written from the author's instructions and the summary of the message it answers, not from the whole message.
  • Telegram. Summaries and answers are sent to the author in a private chat with the author's own Telegram bot. So are the recipients, the subject and the text of a draft the author is asked to approve.
  • Gmail. A draft is created in the author's own mailbox. To address a reply, and to check before the author is asked that the reply goes to the person who wrote, Jarvis reads from Gmail the headers of the message it answers (sender, subject and message id) and the sender and message id of the other messages in its thread, never their text; the headers stay on the author's computer. When the author approves a draft, it is sent from that mailbox to the recipients the author was shown, and to nobody else.
  • The author's computer. Jarvis stores a summary row for each message (sender, subject, category, priority, short summary, requested actions, deadlines) in a database on the author's own computer. It does not store message bodies. For each draft the author is asked to send, it keeps the recipients, the subject, the text, the sender of the message it answers and the author's answer, in the same database. The Google sign-in token is kept in a file on that computer that only the author's user account can read. Because Jarvis can send mail, that token can send mail as the author, so it is treated like a password; the author can withdraw it at any time (see below).

Nothing is sold. Nobody other than the author reads the data; mail goes to someone else only when the author approves it. Jarvis does not use the data to train AI models.

Limited use

Jarvis's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Keeping and deleting data

Summaries and the records of drafts stay on the author's computer until the author deletes them. Drafts stay in Gmail until the author sends or deletes them. The author can withdraw Jarvis's access to Google at any time at myaccount.google.com/permissions, after which Jarvis can read nothing from Gmail or Calendar and write no drafts, and can delete the stored summaries, the records and the token file.

Changes

If what Jarvis does with Google data changes, this page is updated first and the date above changes.
